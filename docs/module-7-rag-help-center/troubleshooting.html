3. Troubleshooting Common Issues

Overview​

This chapter provides solutions to common issues encountered in humanoid robotics development. The RAG chatbot can assist with troubleshooting, but having a reference for common problems and their solutions can accelerate your development process.

ROS 2 Common Issues​

Node Communication Problems​

Issue: Nodes cannot communicate with each other Symptoms: Publishers and subscribers not connecting, services timing out Solutions:

  1. Check if nodes are on the same ROS domain ID: 
    echo $ROS_DOMAIN_ID
  2. Verify network configuration for multi-machine setups
  3. Check for firewall blocking DDS communication
  4. Ensure all nodes are using compatible ROS 2 distributions

Quick Check:

ros2 node list
ros2 topic list
ros2 topic info <topic_name>

Launch File Issues​

Issue: Launch files fail to start all nodes Symptoms: Some nodes don't start, error messages about executables not found Solutions:

  1. Ensure all packages are properly built: 
    colcon build --symlink-install
    source install/setup.bash
  2. Check executable permissions and paths in launch files
  3. Verify package names match actual package directories
  4. Check for missing dependencies in package.xml

Debugging Launch Files:

ros2 launch <package_name> <launch_file> --dry-run

Parameter Configuration Problems​

Issue: Parameters not being set correctly Symptoms: Nodes operating with default values instead of configured parameters Solutions:

  1. Verify parameter names match exactly (case-sensitive)
  2. Check parameter file format (YAML syntax)
  3. Ensure parameter files are in correct location
  4. Use ros2 param list and ros2 param get to verify

Simulation Environment Issues​

Gazebo Common Problems​

Issue: Gazebo crashes or doesn't start Symptoms: Segmentation faults, graphics errors, model spawning failures Solutions:

  1. Check graphics drivers and OpenGL support
  2. Ensure sufficient system resources (RAM, GPU memory)
  3. Verify model files are properly formatted and accessible
  4. Try running with software rendering if hardware acceleration fails

Environment Variables for Gazebo:

export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:~/models
export GAZEBO_RESOURCE_PATH=$GAZEBO_RESOURCE_PATH:~/gazebo_resources

Issue: Robot falls through the ground or behaves unrealistically Solutions:

  1. Check mass and inertia values in URDF
  2. Verify collision and visual geometries are properly defined
  3. Adjust physics parameters in world file
  4. Check for missing or incorrect joint limits

Isaac Sim Issues​

Issue: Isaac Sim fails to start or runs slowly Symptoms: Long loading times, crashes, poor performance Solutions:

  1. Verify NVIDIA GPU with RT cores is available
  2. Update to latest NVIDIA drivers
  3. Check system meets minimum requirements
  4. Close other GPU-intensive applications

Issue: Sensor data not publishing to ROS 2 Solutions:

  1. Verify ROS bridge is properly configured
  2. Check topic names and message types
  3. Ensure Isaac Sim extensions are enabled
  4. Verify network connectivity between systems

Perception System Troubleshooting​

Camera and Sensor Issues​

Issue: Camera feeds showing no data or distorted images Symptoms: Black screens, incorrect colors, missing depth information Solutions:

  1. Check camera connections and power
  2. Verify camera drivers are properly installed
  3. Test camera with basic tools (v4l2-ctl, guvcview)
  4. Check ROS 2 camera interface configuration

Issue: Point cloud data is sparse or incorrect Solutions:

  1. Verify LiDAR calibration and mounting
  2. Check for interference from other sensors
  3. Adjust sensor parameters for environment
  4. Verify coordinate frame transformations

Computer Vision Problems​

Issue: Object detection failing or showing poor accuracy Symptoms: False positives, missed detections, incorrect classifications Solutions:

  1. Check lighting conditions and camera settings
  2. Verify model is trained on similar environments
  3. Adjust detection thresholds and parameters
  4. Consider retraining with domain-specific data

Navigation and Locomotion Issues​

Navigation Stack Problems​

Issue: Robot fails to navigate to goals or gets stuck Symptoms: Local planner oscillation, global planner failures Solutions:

  1. Check map quality and resolution
  2. Verify sensor data quality and frequency
  3. Adjust costmap parameters for robot size
  4. Ensure proper localization (AMCL) is working

Issue: Robot doesn't avoid obstacles properly Solutions:

  1. Verify sensor data is being received by navigation stack
  2. Check costmap inflation parameters
  3. Ensure sensors cover robot's footprint
  4. Adjust obstacle detection thresholds

Humanoid Locomotion Issues​

Issue: Robot falls or shows unstable walking Symptoms: Balance loss, joint oscillation, ZMP violations Solutions:

  1. Check center of mass and inertia parameters
  2. Verify joint controller gains are properly tuned
  3. Ensure balance control algorithms are active
  4. Check sensor calibration (IMU, joint encoders)

Hardware Integration Problems​

Sensor Integration Issues​

Issue: Sensors not publishing data or publishing incorrect values Symptoms: Missing topics, unrealistic sensor readings, timeouts Solutions:

  1. Check physical connections and power supply
  2. Verify sensor drivers are properly configured
  3. Check baud rates and communication parameters
  4. Test sensors independently before integration

Actuator Control Problems​

Issue: Joints not responding or moving incorrectly Symptoms: No movement, incorrect positions, safety errors Solutions:

  1. Verify actuator power and communication
  2. Check joint limits and safety parameters
  3. Ensure controller configuration matches hardware
  4. Verify joint state publisher is working

Network and Communication Issues​

ROS 2 Network Problems​

Issue: Nodes on different machines cannot communicate Symptoms: Topics visible only locally, multi-robot communication fails Solutions:

  1. Check network connectivity (ping test)
  2. Verify ROS_DOMAIN_ID is the same on all machines
  3. Check firewall settings for DDS ports
  4. Ensure network interface is properly configured

Common DDS Ports:

  • UDP: 7400-7410 (default range)
  • May vary based on DDS implementation

Real-time Performance Issues​

Issue: Delays in robot response or inconsistent timing Symptoms: Jittery movement, missed control cycles, late messages Solutions:

  1. Use real-time kernel if available
  2. Optimize computational load distribution
  3. Check network latency for remote operations
  4. Profile code to identify bottlenecks

Chatbot-Specific Troubleshooting​

When Chatbot Responses Are Not Helpful​

Issue: Chatbot provides generic or irrelevant responses Solutions:

  1. Be more specific in your questions
  2. Provide more context about your setup
  3. Try rephrasing the question
  4. Use the select-and-ask feature for specific content

Getting More Detailed Information​

Issue: Need more technical depth than provided Solutions:

  1. Ask follow-up questions for more details
  2. Request code examples or implementation specifics
  3. Ask for references to related sections
  4. Request step-by-step procedures

Diagnostic Tools and Commands​

Essential ROS 2 Diagnostic Commands​

# Check system state
ros2 node list
ros2 topic list
ros2 service list
ros2 action list

# Check specific connections
ros2 topic info <topic_name>
ros2 node info <node_name>

# Monitor system performance
ros2 topic echo <topic_name> -n 10
ros2 run rqt_graph rqt_graph

System Monitoring​

# Check system resources
htop
nvidia-smi  # For GPU monitoring
iotop       # For disk I/O monitoring

# Check network connectivity
netstat -tuln
ifconfig

Preventive Measures​

Regular Maintenance Tasks​

  1. System Updates: Keep ROS 2 and dependencies updated
  2. Log Monitoring: Regularly check system logs for warnings
  3. Backup Configurations: Maintain backups of working configurations
  4. Documentation: Keep notes on successful configurations and workarounds

Best Practices to Avoid Issues​

  1. Incremental Testing: Test components individually before integration
  2. Version Control: Use git for all configuration files
  3. Environment Isolation: Use workspaces properly
  4. Documentation: Keep detailed notes on custom configurations

When to Seek Additional Help​

Escalation Guidelines​

  • Simple Issues: Use chatbot and documentation first
  • Complex Issues: Combine chatbot with official documentation
  • Hardware Issues: Contact hardware vendor support
  • Advanced Debugging: Seek expert consultation

Community Resources​

  • ROS Answers: Community Q&A platform
  • GitHub Issues: For specific software problems
  • Forums: Project-specific community forums
  • Documentation: Official documentation for each component

Summary​

This chapter has provided troubleshooting guidance for common issues in humanoid robotics development, organized by system component. The RAG chatbot can provide additional context-specific help for these issues. When troubleshooting, always start with the most basic checks (connections, power, basic commands) before moving to complex diagnostics. Keep detailed logs and notes during troubleshooting to help identify patterns and prevent future issues. Remember that many issues have simple solutions, so systematic debugging often reveals the root cause quickly.
